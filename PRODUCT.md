# SleekViber

SleekViber is an upcoming web coding platform. Its stated direction is to bring original design, working user journeys, connected data, and trust beneath every click into the same build. These remain goals under development.

The implemented product in this repository is a coming-soon site for people who build websites with AI. It explains the intended direction and gathers feedback about demand and friction. The main action leads to a two-question questionnaire.

The public journey consists of a centered “Beyond almost.” hero over a continuous immersive color field, three scroll-stacking interactive problem scenes covering ten defects, kinetic type and a scroll-driven wire landscape with a fully fitted static signature, a connected map of six intended standards, a guided two-step survey with optional public aggregate results, and a coming-soon close with an optional waitlist and responsive wordmark. The hero presents the goal of vibe coding for the whole website through a short explanation of original design, connected data and complete user journeys, a stationary paper-pill survey action and candid development status. Its composition and word entrance adapt Aceternity's free Hero Section One; the original React Bits ColorBends shader supplies the background, customized to the established vermilion family. Stable local dark scrims keep the message and footer readable while the surrounding bands move. A labeled pause control stops the background; unpressed mouse movement adds bounded pointer influence. Animation stops when hidden or offscreen, and reduced motion retains a static shader frame without pointer response or word entrance. A CSS still remains readable while the visual loads or if WebGL, shader compilation, context or the dynamic visual module fails; a local error boundary isolates module/render failure from the message and actions, and unavailable motion disables its control. The headline stacks below 600px, with the footer continuing in document flow on short screens. Covered desktop problem scenes become inert; the scenes return to accessible normal flow on smaller screens and with reduced motion. Their Form→Logic→Data and Visitor/Member studies are explicitly illustrative. The standards map keeps six fixed controls and updates the existing descriptions, with a finite beam on the selected path and a two-column mobile navigator. The questionnaire retains answers across Back/Next, saves interest and pain-point selections without requesting names or email addresses, and shows a saved receipt after a successful server response. Closing copy and the optional email form sit over a lazy-loaded Threads field with pause, visibility and reduced-motion handling; unavailable decoration leaves the content and form usable. Local development uses SQLite; a configured Neon connection enables hosted PostgreSQL for serverless deployment. The private admin dashboard summarizes responses behind authentication.

Visitors can open aggregate results below the form without an admin account or submitting a vote. Results include the current questionnaire's total responses, today's count in UTC, and counts and percentages for each interest and pain-point option. Multiple pain choices mean their percentages may add up to more than 100%. Results refresh every 30 seconds while open, with manual refresh and readable loading, empty and retryable error states. The public endpoint exposes only total/today/q1/q2 aggregates; it excludes legacy-questionnaire responses, individual answers, response IDs, fingerprints, email addresses, waitlist size and start telemetry. These are current feedback totals, not a representative poll.

Survey topics include frontend design, backend failures, database issues, authentication and access, security, search visibility, and incomplete journeys. Responses help prioritize development; they do not establish market-wide statistics.
