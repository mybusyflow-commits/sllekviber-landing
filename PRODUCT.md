# SleekViber

SleekViber is an upcoming web coding platform. Its stated direction is to bring original design, working user journeys, connected data, and trust beneath every click into the same build. These remain goals under development.

The implemented product in this repository is a coming-soon site for people who build websites with AI. It explains the intended direction and gathers feedback about demand and friction. The main action leads to a two-question questionnaire.

The public journey consists of a left-aligned “Beyond almost.” hero with a studio-lit 3D website study, three scroll-stacking interactive problem scenes covering ten defects, kinetic type and a scroll-driven wire landscape with a fully fitted static signature, six contextual concept panels paired with intended-standard accordions, the survey with optional public aggregate results, and a coming-soon close with an optional waitlist and responsive wordmark. The hero presents the product direction, a stationary paper-pill survey action and development status. Its illustrative Form & Field laptop has two fixed view controls: “The website” and “Look inside”; the latter reveals a request lifecycle and access boundaries. A separate pause control stops the floating motion. The scene uses bounded mouse tilt without drag or orbit, pauses when hidden or offscreen, respects reduced motion and retains a readable still view if WebGL or an asset fails. Below 900px the hero becomes a normal-flow stack. Below 768px, “Look inside” also provides readable HTML explanations of validation, saved records and permissions beneath the controls. The problem scenes return to normal flow on smaller screens and with reduced motion. The questionnaire saves interest and pain-point selections without requesting names or email addresses and remains visible after voting. Local development uses SQLite; a configured Neon connection enables hosted PostgreSQL for serverless deployment. The private admin dashboard summarizes responses behind authentication.

Visitors can open aggregate results below the form without an admin account or submitting a vote. Results include the current questionnaire's total responses, today's count in UTC, and counts and percentages for each interest and pain-point option. Multiple pain choices mean their percentages may add up to more than 100%. Results refresh every 30 seconds while open, with manual refresh and readable loading, empty and retryable error states. The public endpoint exposes only total/today/q1/q2 aggregates; it excludes legacy-questionnaire responses, individual answers, response IDs, fingerprints, email addresses, waitlist size and start telemetry. These are current feedback totals, not a representative poll.

Survey topics include frontend design, backend failures, database issues, authentication and access, security, search visibility, and incomplete journeys. Responses help prioritize development; they do not establish market-wide statistics.
