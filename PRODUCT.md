# SleekViber

SleekViber is an upcoming web coding platform. Its stated direction is to bring original design, working user journeys, connected data, and trust beneath every click into the same build. These remain goals under development.

The implemented product in this repository is a coming-soon site for people who build websites with AI. It explains the intended direction and gathers feedback about demand and friction. The main action leads to a two-question questionnaire.

The public journey consists of a centered “Beyond almost.” hero over a continuous immersive color field, three scroll-stacking interactive problem scenes covering ten defects, kinetic type and a scroll-driven wire landscape with a fully fitted static signature, a connected map of six intended standards, a guided two-step survey with optional public aggregate results, and a coming-soon close with an optional waitlist and responsive wordmark. The hero presents the goal of vibe coding for the whole website through a short explanation of original design, connected data and complete user journeys, a stationary paper-pill survey action and candid development status. Its composition and word entrance adapt Aceternity's free Hero Section One; the original React Bits ColorBends shader supplies the background, customized to the established vermilion family. Stable local dark scrims keep the message and footer readable while the surrounding bands move. Hero and closing motion runs automatically while visible, with no visible Play/Pause controls. Unpressed mouse movement and passive touch input add bounded pointer influence; touch release or cancellation resets the response without intercepting native scrolling. Animation stops when hidden or offscreen, and a live device reduced-motion preference keeps static shader frames without pointer response or hero word entrance. Motion resumes only when reduction is disabled and the surface is eligible. An animated CSS color field remains readable while the hero visual loads or if WebGL, shader compilation, context or the dynamic visual module fails; a local error boundary isolates module/render failure from the message and actions. The CSS fallback follows the same visibility and reduced-motion gates. The headline stacks below 600px, with the footer continuing in document flow on short screens.

Problem scenes stack and overlap at all widths when motion is enabled. On narrow screens, tall chapter copy scrolls before an adaptive pin brings its interaction panel into view. Fully covered scenes become inert and regain eligibility when uncovered; reduced motion restores accessible normal flow. Their Form→Logic→Data and Visitor/Member studies are explicitly illustrative. Connected request routes loop while active and in view. The standards map keeps six fixed controls and updates the existing descriptions; only the selected beam loops while visible. Mobile places the same core between the top and bottom choices in a two-column navigator and preserves visible SVG connections. Variable type responds to pointer input and to scroll on coarse-pointer screens. The questionnaire retains answers across Back/Next, saves interest and pain-point selections without requesting names or email addresses, and shows a saved receipt after a successful server response. Closing copy and the optional email form sit over a lazy-loaded, automatically animated Threads field with visibility and live reduced-motion handling; an animated CSS field preserves atmosphere if decoration is unavailable while leaving the content and form usable. Local development uses SQLite; a configured Neon connection enables hosted PostgreSQL for serverless deployment. The private admin dashboard summarizes responses behind authentication.

Visitors can open aggregate results below the form without an admin account or submitting a vote. Results include the current questionnaire's total responses, today's count in UTC, and counts and percentages for each interest and pain-point option. Multiple pain choices mean their percentages may add up to more than 100%. Results refresh every 30 seconds while open, with manual refresh and readable loading, empty and retryable error states. The public endpoint exposes only total/today/q1/q2 aggregates; it excludes legacy-questionnaire responses, individual answers, response IDs, fingerprints, email addresses, waitlist size and start telemetry. These are current feedback totals, not a representative poll.

Survey topics include frontend design, backend failures, database issues, authentication and access, security, search visibility, and incomplete journeys. Responses help prioritize development; they do not establish market-wide statistics.
