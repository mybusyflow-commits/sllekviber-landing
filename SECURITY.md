# Security and availability review — 14 October 2026

The local outage was caused by the preview server not listening on port 3005. `npm run preview` now launches a detached, hidden process, verifies storage readiness and reuses a healthy existing server. It does not stop an unrelated service occupying the port. Development and production foreground commands also default to 3005. This is local availability; it does not create a public deployment or restart automatically after a computer reboot.

## Changes

- JSON endpoints require the correct content type and enforce 4 KiB on actual streamed bytes, including chunked requests. Reads time out after 10 seconds and reject malformed JSON/UTF-8.
- Cross-site browser requests and mismatched full origins are rejected. Checks use the requested Host authority rather than Next's internally normalized localhost URL; arbitrary local forwarded host/protocol headers are ignored. Vercel's trusted HTTPS edge is accounted for. Public APIs remain callable by non-browser clients; this is not proof of a unique person.
- Persistent, atomic database counters enforce poll, results, waitlist, survey-start and admin-login limits. Login accepts five requests per trusted address per 15 minutes, including successful requests. Buckets expire and survive process restarts. Vercel's protected forwarded address is used on Vercel; arbitrary local forwarded headers are ignored. Counters store hashed keys instead of raw addresses.
- SQLite serializes duplicate checks and inserts within one write transaction, with a bounded busy timeout. Neon uses an advisory transaction lock. SQL parameters remain bound rather than concatenated from user input.
- Admin credentials must meet minimum lengths and reject example placeholders. Password checks compare fixed-length digests in constant time. Signed sessions reject malformed values, expire in seven days, and are invalidated by changing the password or session secret. Production cookies use HttpOnly, Secure and SameSite=Strict. Logout deletes the cookie with matching flags; it does not revoke a previously copied session token.
- Public results query aggregates only. Private analytics have both route-level session checks and proxy protection, with caching disabled. Storage errors return generic messages.
- Global headers add CSP, frame blocking, MIME sniffing protection, referrer and permissions restrictions. Production adds HSTS. CSP permits inline scripts/styles for the current static Next.js page and animation system, WebAssembly for the local Draco model decoder, and local blob fetches for GLB textures. General JavaScript eval is allowed only in development. This CSP is containment, not a complete defense against arbitrary inline-script injection.
- An optional confetti failure no longer reports a successfully saved vote as failed. Login and waitlist handlers guard repeated pending submissions. Logout reports a network failure instead of pretending success. Client requests bound header and body waits to 15 seconds, results/dashboard refreshes cannot overlap, hidden dashboards stop polling, and survey choices are locked while saving.
- The mobile menu focuses its first link when opened and restores focus to its toggle on Escape. Paragraphs avoid lone-word last lines. Motion controls explain unavailable/loading/reduced-motion states; result announcements use singular/plural grammar.

## Verification

`npm run build`, `npm run lint`, `npm run test:security`, and `npm run test:database` cover the production application and isolated temporary databases. Integration checks exercise pages, generated assets, local 3D resources, request rejection, cookies, private/public results, concurrent voting across two processes, login limits across restarts, and expiry recovery. They do not create votes in `data/survey.db`.

The local database passed its integrity check and retained 3 current responses, 4 starts, 0 waitlist entries and 6 legacy responses. The detached preview was checked again after its launcher exited; logs now live outside the build directory. The old error tab could not be inspected under the browser tool's security policy. After the user reopened the website, a fresh HTTP tab was used for live desktop, intermediate and mobile checks. An isolated production preview completed a survey, updated aggregate results, saved a test waitlist email, and completed admin login/refresh/logout. This did not alter the real database. See VERIFICATION.md for evidence and screenshots.

## Dependencies and remaining deployment work

`npm audit --omit=dev --json` reported **zero known production advisories**. The full audit reported five high findings in one development-only dependency chain: `eslint-config-next` → `@next/eslint-plugin-next` → `fast-glob` → `micromatch` → `braces`. [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) lists no patched braces version. The suggested downgrade to Next 14 lint tooling was not applied to this Next 16 project. Do not pass untrusted glob patterns into development tooling; recheck for an upstream patch. Audit results describe published advisories, not a guarantee of no vulnerabilities.

[Next.js announced an upstream security update planned for 14 October](https://nextjs.org/blog/upcoming-nextjs-security-update-october-2026), without published impact/affected-version details at the time of this review. The installed 16.3.8 is the newest published 16.3 version found in the registry during this review. Recheck release advisories before public launch and apply the applicable patched release when available.

A Vercel project has been created through the connected account, but has no deployment. `DATABASE_URL` is still missing. The existing SleekViber Neon project was visible when its connection became available, but connection-string/SQL capabilities are not available in this session. Its schema must be initialized (including `request_limits`), and local records migrated and verified before accepting public votes. No hosted persistence test or deployment verification has been completed. Keep credentials server-only, configure the admin variables in Vercel, and use separate preview/production database branches. SQLite is local storage, not durable Vercel function storage. See README.md for the exact setup/migration commands.
